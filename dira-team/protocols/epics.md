# 에픽 - epic: 값의 형식 - 라벨 - 여는 시점 - 자리 - 경계 - 쓰는 시점

이 파일이 정본이다. 세션이 실제로 쓸 때 필요한 여섯 - 값의 형식, 라벨, 여는 시점, 자리,
경계 한 문장, 쓰는 시점.

## 값의 형식

- 티켓 frontmatter 키는 `epic:` 하나다. 값은 로드맵 P번호 본체 하나 - 예 `P273`.
  `P273-2`는 그 에픽의 행 ID지 에픽이 아니다.
- 목록이 아니다. `deps:`와 달리 `[...]`로 쓰지 않는다 - 티켓 하나는 에픽 하나에 든다.
- 파싱하지 않는다. 문자열 그대로가 키다 - `epic: P273`과 `epic: P273-2`는 서로 다른
  에픽으로 선다. 접두사를 벗기거나 정규화하는 규칙을 만들지 않는다(만들면 그 규칙이
  둘째 정본이다).
- `epic:`이 없는 티켓이 정상이다 - 화면에서 `(에픽 없음)` 하나로 모인다.

## 라벨 - `epics/<P번호>/README.md` 첫 줄. 키와 다른 것을 담는다

`P273`만 뜨는 목록은 사람이 못 읽는다(사람 지적, 2026-08-14). 그래서 **키와 라벨이 갈린다.**

| | 키 | 라벨 |
|---|---|---|
| 무엇 | `P273` | `에픽 - P번호를 frontmatter로 승격한다` |
| 사는 곳 | 티켓 fm `epic:` | `<루트>/epics/<P번호>/README.md` **첫 줄** |
| 읽는 쪽 | 기계 | 사람. 화면에 선다 |

- **에픽을 여는 동작은 두 줄이다** - 로드맵에 `### P###.` 블록을 세우고, 같은 자리에서
  `epics/<P번호>/README.md`를 만들어 첫 줄에 제목을, 그 뒤에 본문을 적는다. 둘 다 pm이 한다.
- **제목과 내용 둘 다 필수다.** 선택이 아니다 - `제목`은 README 첫 줄, `내용`은 **그 첫 줄 뒤
  본문**이고, 둘 중 하나만 든 README는 안 연 것과 같다. 판정은 하나뿐이다 - 공백을 뺀 글자가
  하나라도 있으면 있는 것이다(최소 길이도 형식도 안 본다).
- **어긴 것은 화면이 고발한다.** 제목이 없으면 화면 셋(사이드바 항목 - 칸반 띠 머리 - 에픽
  화면 머리)이 `제목 없음 (P273)` + 표식으로 뜨고, README 자체가 없으면 `README 없음` 배지가
  선다. 조용히 P번호만 띄우지 않는다 - 빠진 것은 빠졌다고 보여야 사람이 채운다. 다만
  **내용이 빈 것을 고발하는 자리는 에픽 화면 하나뿐이다** - 목록 쪽이 세우는 표식은 제목
  하나라, 본문이 섰는지는 여는 세션이 자기 손으로 확인한다.
- **값을 늘려서 풀지 않는다.** `epic: P273-사이드바`처럼 적으면 키에 파싱 규칙이 생긴다.
  키는 `P273` 그대로이고 라벨은 다른 파일에 따로 산다 - 담는 것이 달라서 정본이 안 갈린다.
- **README 첫 줄 뒤 본문**은 이 에픽이 무슨 작업인지 사람이 적어 두는 자리다. 에픽 화면이
  머리 아래에 그대로 그리고, 빈 채로 남았으면 같은 화면에서 채운다.
- 로드맵 `### P###.` 제목과 README 첫 줄이 어긋나면 **README가 이긴다** - 앱이 읽는 것이
  그것이고, 앱은 로드맵 문서를 안 판다.

## 여는 시점 - 갈래 셋 (요구 `e49c7b23`)

로드맵 `### P###.` 블록을 세우는 판단은 셋으로 갈린다.

- **규모** - pm이 보기에 일이 에픽 단위로 크다.
- **명시화** - 규모는 크지 않지만 이 작업을 에픽으로 못박아 둬야 한다고 pm이 판단한다.
- **사람이 직접** - 화면의 에픽 만들기 입구로 사람이 연다(결정 17). 이 갈래도 제목의 정본은
  README 첫 줄이다 - 화면이 쓰는 것은 그 파일 한 장뿐이고, 로드맵 `### P###.` 블록은 화면이
  안 쓴다(앱은 스펙 문서를 안 판다).

앞의 둘은 pm의 판단 기준이고, 셋째는 화면이 그 손을 대신한다 - 자리가 다를 뿐 여는 동작
자체(§라벨의 그 두 줄, 셋째는 README 한 줄)는 갈리지 않는다.

## 자리

`<TICKET_ROOT>/epics/<P번호>/memory/*.md` - `personas/` `ontology/` `protocols/`의
형제, 큐의 넷째 사이드카다.

- 형식은 OKF 그대로(페르소나 메모리와 같다) - 파일 하나 = 개념 하나, `[[링크]]`, 사람이
  읽고 고친다.
- 글롭은 한 단계 `memory/*.md`뿐이다. 하위 디렉터리는 안 읽는다.
- 디렉터리는 세션이 만든다(`mkdir -p`) - 처음 메모리를 남기는 순간 생긴다. GUI는 안
  만든다.
- 없으면 정상이다. 경고 없다.

## 경계 - "다른 에픽이 읽어서 참인가"

> 다른 에픽의 세션이 읽어서 참이면 온톨로지나 페르소나 메모리이고, 이 에픽 안에서만
> 참이면 에픽 메모리다.

- 예 - 온톨로지: "티켓 스토어가 무엇인가". 페르소나 메모리: "남이 올린 보고는 다시 잰다".
  에픽 메모리: "P273의 사이드바 폭은 240px로 합의됐다", "`?group=`을 먼저 시도했다가
  접었다 - 사유".
- `epic:`은 검색 표면을 안 좁힌다 - `ontology/` `personas/*/memory/` 스펙 문서는 여전히
  전역이다. 좁히는 것은 에픽 메모리 하나뿐이다.
- 온톨로지 카드에 에픽 태그를 달지 않는다 - 개념 하나가 여러 에픽에 쓰이므로 태그를
  달면 카드가 두 벌이 된다.

## 쓰는 시점

CORE.md §회고와 같은 자리다 - `## 결과`를 쓰기 직전, 그 에픽의 티켓을 수행한 세션이
"이 에픽 안에서만 참인가"를 판단해서 쓴다. 남길 것이 없으면 안 쓴다(빈손이 정상).
