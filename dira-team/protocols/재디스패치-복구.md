# 재디스패치 - 앞 세션의 산출물을 찾아온다

인라인 `AGENTS.md` §git에서 내려온 세부다. 트리거는 하나 - **받은 티켓에 `## 결과`나
`## 블록`이 이미 붙어 있고, 적힌 산출물이 `main`에 없다.**

## 그 글은 검증이 아니라 주장이다

앞 세션이 `## 결과` 마지막 줄에 `커밋 + push 성공`까지 적어 놓고 **커밋을 하나도 안 한 채**
죽는 일이 있다. 적힌 커밋 해시를 세지 말고 **산출물이 통합 브랜치에 있는지 내용으로**
확인한다 - `git log --oneline dev -- <파일>` 또는 `grep`. 있으면 그대로 이어서
하고, 없으면 처음부터 다시 쓰기 전에 아래를 본다.

## 워커가 여럿이면 다른 트리에 남아 있다

재디스패치는 같은 워커로 온다는 보장이 없고 **앞 워커 이름은 티켓에 안 남는다**(디스패치가
`owner:`를 자기 워커로 덮어쓴다). 그래서 전부 훑는 것이 유일한 길이다:

```
$ for w in /Users/hsol/Projects/hsol.info/.dira/worktrees/*/; do \
    printf '%s: ' "$(basename "$w")"; git -C "$w" status --porcelain | wc -l; done
```

**`-uno`를 붙이지 않는다.** 앞 세션이 만든 것이 **새 파일**이면 `-uno`가 그것을 못 보고
`0`을 준다 - 깨끗하다고 읽고 산출물을 처음부터 다시 쓰게 된다.

- **더러운 트리가 나오면 산 세션이 쓰고 있는지 먼저 본다.** `grep -l '^owner: .* / <워커>-'
  .dira/tickets/*.wip.md` - 나오는 것이 있으면 그 트리는 **지금 도는 세션의 작업 트리**다.
  내 티켓 것이 아니라고 보고 **손대지 않는다**.
- 내 산출물이면 가져온다: `git -C <그 트리> diff HEAD > /tmp/<내 해시>.patch` -> 내 트리에서
  `git apply`. **미추적 파일은 diff에 안 들어간다** - `git -C <그 트리> ls-files -o
  --exclude-standard`로 세어 보고 있으면 따로 복사한다.
- **가져온 뒤 그 트리를 정리한다** - `git -C <그 트리> restore .` + 복사한 미추적 파일 삭제.
  안 하면 그 워커의 다음 세션이 `git rebase dev`에서 막혀 티켓 하나를 헛으로
  태운다.

`push-거부.md`의 *남의 트리를 고치지 않는다*는 **받는 트리**(사람의 편집이 섞이는 자리)
규약이다. 여기는 세션만 쓰는 워커 트리이고, 산 세션이 없다는 것을 방금 확인했다.
