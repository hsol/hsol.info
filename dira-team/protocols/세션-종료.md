# 세션이 끝나는 자리 - 턴을 닫을 때와 미완으로 넘길 때

인라인 `AGENTS.md` §턴을 닫으면 세션이 끝난다 - §미완으로 끝날 때에서 내려온 세부다.

## 판별표 - 벽, 자발 중단, 한도는 서로 다른 자리로 간다

**`## 블록`은 사람이 답을 써야만 풀리는 자리에만 쓴다.** 남은 일이 무엇인지 세션이 아는 채로
멈추는 것(**자발 중단**)은 블록이 아니다. 가르는 질문은 둘이다.

| 세션이 멈춘 이유 | 사람이 답을 쓰면 이 자리가 풀리나 | 지금 이 턴에 글을 쓸 수 있나 | 자리 |
|---|---|---|---|
| **벽** - 스펙 모순, 읽기 전용 영역, 새 의존성, push 반복 실패 | 예 | 예 | `## 블록` + `.wip` 유지 (CORE - When blocked) |
| **자발 중단** - 턴이 모자란다, 남은 범위가 있다, 뒤 세션이 이으면 된다 | **아니오** | 예 | 아래 미완으로 끝날 때 절 - `## 진행 기록` + 이어받기 한 장 + `.done` |
| **한도** - 왕복이 이미 거절되고 있다(토큰 회전 훅을 쓰는 프로젝트만) | 아니오 | **아니오** | `한도.md` - 본문에 아무것도 안 적고 `unassign` |

첫 질문이 벽과 나머지를 가르고, 둘째 질문이 자발 중단과 한도를 가른다. 인라인 `AGENTS.md`
미완으로 끝날 때 절과 한도를 만났을 때 절이 각 자리에서 이 두 질문을 되묻는다.

## 턴을 닫으면 세션이 끝난다 - 알림을 기다리는 자리가 없다

엔진의 감시 루프가 마지막 줄이 `result`인지 보고 그 자리에서 세션을 끝낸다 - MAXRUN은 그 줄이
영영 안 오는 경우를 위한 것이지, 세션이 스스로 끝을 미루는 자리가 아니다. 백그라운드로 던진
작업(테스트-빌드 등)의 알림을 받을 창이 없다 - 알림이 와도 세션은 이미 없다.

- 백그라운드로 띄웠으면 결과를 **같은 턴 안에서** 받는다. 전경에서 돌리거나, 길면 폴링을
  계속한다 - 던지고 턴을 닫지 않는다.
- **`## 진행 계획`을 든 티켓이 특히 위험하다.** 계획 단위로 끊어 일하는 모양이 "이 단계는
  백그라운드에 걸고 다음으로 넘어간다"는 오해와 붙기 쉽다.

## 미완으로 끝날 때 - 다섯 줄 순서

`## Done when` 박스를 다 못 채웠는데 이번 턴으로 끝내야 한다고 판단했으면 - **판단 주체는
세션 자신이다** - 죽지 말고 넘긴다. **push가 맨 앞이다**(완료 트리거와 같은 이유 - 통합 안 된
작업이 완료로 기록되면 안 된다):

1. 여기까지 참인 `## Done when` 박스를 `- [x]`로 켜고 못 채운 것은 `- [ ]`로 둔다.
2. 이 프로젝트의 push 절차를 그대로 따른다(인라인 §git).
3. 이어받기 티켓 **한 장**을 발행한다(쪼개지 않는다). `handoffs:` 값은 원본 값 + 1(아래
   이어받기를 넘으면 절 참고).
4. 원본 프론트매터에 `continued: <새 해시>` 한 줄.
5. `## 진행 기록`에 어디까지 왔는지를 적고(아래 `## 진행 기록` 절), `## 결과`에는
   `-> <새 해시> 남은 범위` + push한 커밋만 적는다. 아카이빙을 쓰는 프로젝트면 완료 트리거대로
   아카이브 티켓을 낸 뒤 `.done`으로 rename.

이어받기 티켓의 모양:

| 키 | 값 |
|---|---|
| `persona` | 원본과 같다. 남은 일은 남은 사람의 일이다 |
| `epic` `req` | 쓰고 있었다면 원본 값을 그대로 물려받는다 |
| `deps` | **안 건다.** 원본이 곧 `.done`이 되고 하드 선후가 아니다 |
| 본문 `## Goal` | 남은 범위. 원본 stem을 한 줄로 가리킨다 |
| 본문 `## Done when` | 원본에서 못 채운 박스를 그대로 옮긴다 |
| `handoffs` | 원본 값 + 1(없으면 원본이 0). 상한을 넘으면(아래 이어받기를 넘으면 절) claim이
  실패하고 답변 대기로 올라간다 |

- **`## 진행 계획`을 들고 있었으면 남은 계획 줄이 그대로 이어받기 티켓의 계획이 된다.**
- **이어받기 티켓에 진행 기록을 복사하지 않는다** - `## Goal`이 원본 stem을 가리킨다(아래
  `## 진행 기록` 절).
- **`## 블록`이 아니다.** 사람이 답할 것이 없다 - 남은 일이 무엇인지는 세션이 안다. CORE의
  When blocked 목록에 있는 "won't fit one session (propose a split, stop)" 한 줄을 이 절이
  이 자리에서 **대체한다** - 이미 일부가 통합된 뒤라면 멈춰 서서 사람을 부르는 것보다 남은
  것을 한 장으로 넘기는 것이 싸다.
- **한도(`한도.md`)는 이 절이 아니다.** 가르는 질문 둘 - **사람이 답을 쓰면 이 자리가
  풀리나**(아니오), **지금 이 턴에 글을 쓸 수 있나**(예) - 둘 다면 이 절, 거절되면 한도다.

## `## 진행 기록` - 다음 세션이 읽는 절, `## 결과` 바로 앞

- **자리는 원본 티켓 본문, `## 결과` 바로 앞.** 어디까지 왔는지는 이 절이 들고, `## 결과`는
  종전대로 닫는 글(`-> <새 해시> 남은 범위` + push한 커밋)만 든다.
- **무엇을 적나** - 어디까지 했나, 무엇을 시도했고 왜 안 됐나, 다음 세션이 같은 벽에 다시
  머리를 박지 않게 하는 사실. 검증 명령과 실제 출력은 종전대로 `## 결과`다.
- **왜 `## 결과`가 아닌가** - 독자가 다르다. `## 결과`는 티켓을 닫는 글이라 사람이 읽고, 진행
  기록은 **다음 세션이** 읽는다. 한 절에 섞으면 닫는 글이 길어져 요약을 못 잡는다.

## 이어받기를 넘으면 사람이 받는다 - `handoffs:`

사슬이 무한히 길어지면 이어받기가 영원한 재디스패치가 된다.

- **frontmatter 키 - `handoffs: <n>`.** 이어받기 티켓에만 붙고 값은 원본 값 + 1이다. 키가
  없으면 0으로 읽으므로 첫 이어받기가 `handoffs: 1`이다.
- **상한은 프로젝트가 정한다(예: 3).** 상한을 넘긴 티켓이 디스패치되지 않고 답변 대기로
  올라간다 - 원본 + 상한 장까지는 사람을 안 부른다.
- **판정 자리는 엔진의 claim이다** - 원자적 link에 성공한 뒤 frontmatter를 읽고, 넘었으면
  release -> ask_human -> 실패로 끝낸다. `awaiting`이 이미 있으면 다시 걸지 않는다(영구 루프
  방지).
- **`handoffs`는 운영 키지 요구사항 레이어의 키가 아니다** - 세션이 손으로 쓸 일은 이어받기
  티켓 발행 시 값을 채우는 것뿐이다.
